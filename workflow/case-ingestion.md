# 案例摄取工作流

## 最小输入

只要求 `input.original_prompt`。成片、模型、平台、评分、来源、节奏拆解和人工观察全部可选。没有成片时不要要求多模态分析，也不要把案例判为失败。

## 处理步骤

1. 保留原始提示词，不改写证据正文。
2. 检查空内容、明显冲突、重复、危险绕过和不当内容。
3. 从文本中提取平台、生成方式、内容类型和可复用结构；不确定时留空。
4. 纯提示词规律标记“待验证”，不直接写入通用硬规则。
5. 自动生成案例编号、标题、日期、证据等级和去重指纹。
6. 使用 `python tools/ingest_case.py <案例.yaml>` 入库并更新索引。

## 证据等级

- `prompt_only`：只有原始提示词。
- `user_reported`：用户补充结果描述。
- `output_observed`：已提供并实际观察输出。

用户明确说明成功时可以标记 `proven`，但必须保留真实证据等级，不能伪装成已观察成片。

## 规律拆解

分别记录：可复用项、避免项、模型专属项、待验证推断。重点按“平台 + 模型版本 + 生成方式 + 内容类型”检索，避免跨模型生搬硬套。
